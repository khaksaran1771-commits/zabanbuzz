# 0004. اجرای migration در سرویس جداگانه

- **وضعیت:** پذیرفته
- **تاریخ:** 2026-11-06

## مسئله

پیش از شروع برنامه، پایگاه داده باید به‌روز باشد. ایمیج نهایی Prisma CLI ندارد.

## تصمیم

سرویس `migrate` در compose از مرحله `builder` ایمیج استفاده می‌کند، `prisma migrate deploy` را یک بار اجرا می‌کند و خارج می‌شود. سرویس `app` فقط پس از موفقیت آن شروع می‌شود.

## گزینه‌های ردشده

- **اجرای migration در شروع کانتینر `app`:** باید CLI به ایمیج نهایی اضافه شود، و اگر چند نمونه از برنامه اجرا شود، هم‌زمان migration می‌زنند.
- **اجرای دستی:** به‌راحتی فراموش می‌شود.

## پیامدها

اگر migration شکست بخورد، برنامه بالا نمی‌آید و خطا را در `docker compose logs migrate` می‌توان دید. این رفتار عمدی است.
