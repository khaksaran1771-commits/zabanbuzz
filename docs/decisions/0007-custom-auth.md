# 0007. احراز هویت درون‌پروژه‌ای با نشست در پایگاه داده

- **وضعیت:** پذیرفته
- **تاریخ:** 2026-11-06

## مسئله

کاربران باید با ایمیل یا شماره موبایل وارد شوند. بسیاری از کنکوری‌ها فقط موبایل دارند، پس ایمیل نباید اجباری باشد. کدها باید بعداً از سرویس‌های پیامک ایرانی ارسال شوند.

## تصمیم

یک ماژول کوچک در `src/lib/auth/`:

- رمز عبور با scrypt از خود Node هش می‌شود.
- نشست در جدول `Session` است و فقط هش توکن ذخیره می‌شود. کوکی `httpOnly` است، و در production هم `Secure`.
- هر درخواست نشست و نقش را از پایگاه داده می‌خواند، پس خروج و تغییر نقش فوری اعمال می‌شود.
- پس از ۵ تلاش ناموفق برای یک شناسه، ورود ۱۵ دقیقه بسته می‌شود.
- پیام خطای ورود فاش نمی‌کند که حساب وجود دارد یا نه.

## گزینه‌های ردشده

- **Better Auth یا Auth.js:** مدل این کتابخانه‌ها ایمیل‌محور است و کاربر فقط‌موبایلی در آن‌ها به راه‌حل جانبی نیاز دارد. وابستگی بزرگی هم برای این نیاز ساده می‌آورند. نقطه ضعف انتخاب ما این است که امنیت این کد به عهده خود ماست.
- **کوکی رمزشده بدون پایگاه داده:** نمی‌شود یک نشست یا نقش را فوری باطل کرد.

## پیامدها

- هر صفحه و Server Action باید خودش `requireRole` یا `requireUser` را صدا بزند.
- محدودیت تلاش فقط بر اساس شناسه است، پس کسی می‌تواند با رمز اشتباه، ورود یک حساب را موقتاً ببندد. پیش از انتشار باید محدودیت بر اساس IP هم اضافه شود.
- ثبت‌نام فعلاً نشان می‌دهد که یک ایمیل یا موبایل قبلاً ثبت شده است.
- روی HTTP غیر از localhost، کوکی `Secure` ذخیره نمی‌شود، پس production به HTTPS نیاز دارد.
- اگر نیازهایی مثل ورود با گوگل یا احراز دومرحله‌ای پیچیده اضافه شد، این تصمیم باید بازبینی شود.
