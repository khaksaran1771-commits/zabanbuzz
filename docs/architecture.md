# معماری

## سرویس‌های داکر

| سرویس | کار | طول عمر |
| --- | --- | --- |
| `db` | پایگاه داده PostgreSQL 17، با داده ماندگار در volume به نام `db-data` | دائمی |
| `migrate` | اجرای `prisma migrate deploy` | یک بار اجرا می‌شود و خارج می‌شود |
| `app` | سرور Next.js روی پورت 3000 | دائمی |

ترتیب بالا آمدن: اول `db` سالم می‌شود، بعد `migrate` تمام می‌شود، بعد `app` شروع می‌کند.

## ساختار پوشه‌ها

| مسیر | محتوا |
| --- | --- |
| `src/app/(auth)/` | ورود، ثبت‌نام و actionهای احراز هویت |
| `src/app/(panel)/` | پنل دانش‌آموز، مدرس و ادمین |
| `src/lib/auth/` | نشست، رمز عبور، نقش‌ها، OTP و محدودیت تلاش |
| `src/lib/prisma.ts` | تنها نمونه Prisma Client در برنامه |
| `scripts/make-admin.mts` | ارتقای یک کاربر موجود به ادمین |
| `src/generated/prisma/` | کد تولیدشده Prisma که در گیت نیست |
| `prisma/schema.prisma` | مدل داده |
| `prisma/migrations/` | تاریخچه تغییرات پایگاه داده |
| `prisma.config.ts` | تنظیمات Prisma CLI و آدرس پایگاه داده |
| `docs/` | داکیومنت‌ها و decision log |

## جریان داده

خواندن: یک Server Component در `src/app/` با `prisma` از `@/lib/prisma` می‌خواند. چون Cache Components روشن است، این کامپوننت باید `connection()` را صدا بزند و داخل `Suspense` باشد.

نوشتن: فرم یک Server Action را صدا می‌زند، دسترسی و ورودی بررسی و داده ذخیره می‌شود، و `revalidatePath` صفحه را تازه می‌کند.

## احراز هویت

کوکی `session` یک توکن تصادفی دارد و هش آن در جدول `Session` است. `getCurrentUser` در هر درخواست یک بار کاربر را از پایگاه داده می‌خواند. پنل‌ها با `requireRole` محافظت می‌شوند و هر صفحه و action باید خودش این را صدا بزند، چون بررسی در layout برای محافظت از صفحه کافی نیست. موبایل به شکل `+989xxxxxxxxx` و ایمیل با حروف کوچک ذخیره می‌شود.

## متغیرهای محیطی

فایل `.env` در گیت نیست و نمونه‌اش `.env.example` است. مقدار `DATABASE_URL` در `.env` به `localhost` اشاره می‌کند و مخصوص اجرا روی خود سیستم است. داخل داکر، `docker-compose.yml` آن را با آدرس سرویس `db` جایگزین می‌کند.
